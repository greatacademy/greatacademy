# 学习引擎

> [English](learning-engine.md) | 简体中文

本文规定学习引擎：Great Academy 如何决定学习者下一步做什么，以及每次作答如何改变引擎对学习者的认识。引擎位于 `libs/engine`。它是纯的（没有时钟，除带种子的 `Rng` 外没有随机性，没有 I/O），并且与学科无关：它只看到编译后的知识图谱（[内容](content.zh-CN.md)）和学习者的事件日志。

它实现的教学法见 [Math Academy 之道](the-math-academy-way.zh-CN.md)。书中留有余地之处，本文记录我们的选择及理由；数值集中在 [§8](#8-参数)。

---

## 1. 状态与事件

引擎采用**事件溯源**。数据库把已完成的任务存为事件；学习者状态是对事件的折叠：

```ts
state = replay(ctx, events, initialState);   // 逐个事件调用 applyEvent
```

| 事件 | 记录时机 | 数据 |
| :--- | :--- | :--- |
| `placed` | 某门课程的诊断结束（或被跳过） | 课程；判定为已掌握的知识点；其中哪些被直接提问过 |
| `lesson` | 一节课结束 | 知识点、通过或失败、提问数与答对数 |
| `review` | 一次复习结束 | 知识点、答对数、提问数 |
| `quiz` | 一次测验结束 | 每题一个结果，按知识点 |

状态是推导出来的，因此参数或规则的改变通过重放作用于每位学习者，事件日志也就是每个决定的审计记录。

每个知识点的状态为 `TopicState`：

| 字段 | 含义 |
| :--- | :--- |
| `learned` | 课程已通过，或诊断判定已掌握 |
| `repNum` | 成功的间隔重复次数，可为小数 |
| `last` | 上次重复的有效时间 |
| `speed` | 该学习者掌握该知识点的快慢，取值 [0.5, 1.5]；1 为典型 |
| `failedAt` | 最近一次课程失败的时间 |
| `explicitReviews` | 已做的复习次数，用于分析 |

## 2. 记忆

记忆保持遵循指数遗忘曲线，间隔随每次成功重复而增长：

```
interval(repNum) = min(1 天 · 2.5^repNum, 365 天)
memory(now)      = 2^(−(now − last) / interval(repNum))
```

当记忆降到 0.5，即上次重复后一个间隔时，知识点**到期**：课后 1 天，然后约 2.5、6、16、39 天，依此类推。`repNum` 是小数，因此部分得分会平滑地延长间隔。

## 3. 前沿

课程是学科图谱上的一个视图（[内容 §6](content.zh-CN.md#6-课程)）。课程的**范围**是课程知识点加上其基础；掌握下限及其祖先**视为已知**，不讲授也不复习。

**前沿**是学习者下一步可以学的知识点：在范围内、尚未学会、所有先修都已知。按教学顺序列出（先基础，后课程顺序）。

**失败的课程。** 课程失败的知识点会离开前沿，直到它的每个关键先修在失败之后得到一次重复（显式或隐式）。失败通常意味着某个先修薄弱，因此引擎先修补先修，而不是立即重试同一节课。关键先修是各学习点 `keyPrerequisites` 的并集；都未声明时取直接先修。

## 4. 重复与 FIRe

每次显式重复（一节课、一次复习、一道测验题）都有一个取值 [0, 1] 的**结果**，并沿涵盖边传播。这就是**分数隐式重复**（FIRe）。

**涵盖闭包。** 若 A 以权重 w₁ 涵盖 B，B 以 w₂ 涵盖 C，则 A 以 w₁·w₂ 涵盖 C。存在多条路径时取最大乘积。

**得分（结果 > 0）。** 知识点本身得分 `result`，它涵盖的每个已学知识点得分 `result · w`。得分 f：

- 给 `repNum` 加上 `f · early · speed`；
- 把 `last` 向当前时间移动 f 的比例，使记忆按得分比例恢复。

`early` 对到期前的重复打折：刚重复过（记忆 1）为 0，到期后（记忆 ≤ 0.5）为 1，中间线性。复习仍然新鲜的内容几乎不会加强它，这与间隔效应一致。

学习者**较慢**（speed < 1）的知识点**不接受隐式得分**。在某知识点上吃力的学习者需要显式练习它；来自更难知识点的得分会掩盖弱点。

**惩罚（结果 0）。** 知识点失去一次重复，记忆被重置（`last` = 当前时间），因此很快再次到期。涵盖它的每个已学知识点失去 `w · 0.5` 次重复，但不重置记忆：它们依赖失败的技能，应该更早回来，但它们本身并未被证明已遗忘。

## 5. 任务

`nextTasks` 最多提供六个任务：

1. 学习者在该课程中被定位之前，只提供**诊断**（§9）。
2. 测验到期时（§7），提供**测验**。
3. 到期知识点的**复习**与前沿上的**课程**交替排列，复习在前；连续四次复习之后，课程在前。

**课程占比。** 有课程可学时，至少 25% 的任务是课程。复习从不挤占新学习；而且如下一点所述，新学习也是最便宜的复习方式。顺序同样重要，因为许多学习者总是选第一个任务：状态记录上次课程以来的复习次数，连续四次之后课程排在最前。否则，一个复习屡屡失败、又屡屡到期的学习者可能几周都只在复习。

**重复压缩。** 到期知识点不逐个复习：

1. 保证提供的课程会隐式修复的到期知识点（以权重 ≥ 0.5 被涵盖）先被去掉。
2. 其余的按集合覆盖贪心处理：每一步选择一个已学知识点，它的重复能修复最多尚未覆盖的到期知识点（它自己以及它以权重 ≥ 0.5 涵盖的到期知识点）；平局时优先自身到期的，再优先更高阶的。

这样，一次高阶知识点的复习就能代替其中若干较简单知识点的复习。

## 6. 课程与复习

**课程。** 一节课按顺序走过知识点的各学习点。每个学习点先读讲解和例题，再回答该学习点生成器出的练习题：

- **连续**答对两题，通过该学习点；
- 一旦在五题之内已不可能通过，课程立即**失败**。

要求连对而不是累计答对，侥幸猜对就不够；在五题处停止，避免吃力的学习者反复磨题：引擎会把他们转向先修（§3）。

课程通过后：

- 知识点以 `repNum` 0 记为已学；
- 估计 `speed = 0.5 + fewest / asked`，其中 `fewest` = 学习点数 × 2（完美的一节课得 1.5）；
- 视为对其涵盖知识点的一次完整重复。

**复习。** 一次复习问三道题，从知识点最后（最完整）的学习点开始取题并打乱顺序。答对两题或以上即通过，结果为 `correct / 3`；否则失败（结果 0）。每次复习也调整速度：`speed ← 0.8 · speed + 0.2 · (0.5 + correct / total)`。

## 7. 测验

每获得 150 XP，且已学知识点至少四个时，提供一次测验：八道题，每题一个知识点，没有提示，结束前没有反馈。四分之三的题目来自最近学会的知识点，其余从较早的知识点中抽取。

每道答对的题是一次结果为 0.5 的显式重复，每道答错的题是一次失败（§4）。测验是提取练习式的检验：它能发现模型安排的复习遗漏的问题。

## 8. 参数

| 参数 | 值 | 理由 |
| :--- | :--- | :--- |
| `baseIntervalDays` | 1 | 课后第二天第一次复习，与书中一致 |
| `intervalGrowth` | 2.5 | 间隔重复系统常用的难度系数（SM-2 从 2.5 起） |
| `maxIntervalDays` | 365 | 每个知识点每年至少复习一次 |
| `dueMemory` | 0.5 | 恰好一个间隔后到期；约 50% 保持率时复习既高效，又有足够的"合意困难" |
| `failPenalty` | 1 | 一次失败抵消一次成功重复 |
| `implicitPenaltyScale` | 0.5 | 涵盖它的知识点分担责任，但只分一半，因为它们本身没有被检验 |
| `minCoverWeight` | 0.5 | 只有练到某到期知识点的至少一半，才算修复了它 |
| `minSpeed`、`maxSpeed` | 0.5、1.5 | 速度缩放得分；上下界防止单节课起支配作用 |
| `placedRepNum` | 1（被直接提问 +0.5） | 定位的知识点已掌握但近期未练习；直接答对是更强的证据 |
| `kpStreak` | 2 | 连对两题靠运气不太可能，而真懂的学习者又很快完成 |
| `kpMaxQuestions` | 5 | 容许一两次失误；再多，先修出问题的可能更大 |
| `reviewQuestions`、`reviewPass` | 3、2 | 简短的复习，容许一次失误 |
| `quizEveryXp` | 150 | 按每天 40 XP 约三到四天一次 |
| `quizQuestions`、`quizMinTopics` | 8、4 | 足以广泛抽样，又能一次做完 |
| `quizCredit`、`quizXp` | 0.5、15 | 一道题相当于半次复习 |
| `minLessonShare` | 0.25 | 每四个任务至少一个是新学习 |
| `maxReviewStreak` | 4 | 约半个学习日；没有哪一天只在复习。取三时，课程排到了其先修知识点的复习之前，拖慢了典型学习者 |

这些数值来自书中的描述和我们的判断，而不是数据。路线图 P10 将根据真实学习者的事件日志重新校准，重放使改动对过去同样生效。

**模拟。** `tools/simulate` 用真实内容和引擎让模拟学生学完一门课程。学生答对的概率为 `ability · (0.6 + 0.4 · memory)`，每天学习固定的 XP。在代数基础（20 个知识点）上，每种学生 20 个种子的结果：

| 学生 | 能力、XP/天 | 天数 | 每知识点显式复习 | 失败课程 |
| :--- | :--- | ---: | ---: | ---: |
| 强 | 0.95、40 | 5.7 | 0.24 | 0 |
| 典型 | 0.85、30 | 9.3 | 0.58 | 1.2 |
| 吃力 | 0.70、20 | 20.2 | 1.77 | 6.1 |
| 典型、已会整数 | 0.85、30 | 7.6 | 0.68 | 0.9 |

典型学习者每个知识点不到一次显式复习，因为后面知识点的课程隐式复习了前面的知识点。吃力的学习者得到更多显式练习：他们较低的速度使隐式得分被扣留。模拟器的测试防止这些性质退化。

在代数预备（55 个知识点）上，同样的学生需要更多显式复习：典型学生 30.3 天、每知识点 1.75 次复习，强学生 1.05 次，吃力学生在 59 天里 5.59 次，因为学得慢的学习者也有更多时间让复习到期。它新增的许多单元（数论初步、小数与百分数、根式、比、统计）广而不深：课程中练到它们的后续知识点很少，所以它们的复习较少来自隐式重复。涵盖它们的知识点将随代数一出现。涵盖权重记录的是每个知识点实际练习的内容，不会为了改善这些数字而调高。

```bash
pnpm nx run simulate:simulate                  # 代数基础
pnpm nx run simulate:simulate -- prealgebra    # 其他课程
```

## 9. 诊断

学习者初次进入某门课程时，通过一次自适应诊断定位，诊断范围是该课程范围内尚未掌握的知识点。每门课程有各自的诊断，只做（或跳过）一次（状态中列出已诊断的课程）；在本学科其他课程中已学会的知识点不会再问，没有待定位知识点的课程没有诊断。每次作答解决的不只是所问的知识点：

- **答对**：该知识点及其所有祖先都已掌握；
- **答错**或"我不会"：该知识点及其所有后代都未掌握。

下一题选择使 min(答对时解决的知识点数, 答错时解决的知识点数) 最大的未解决知识点，即在图上做二分查找。n 个知识点的诊断最多问 min(n, 4 + ⌈2·log₂(n+1)⌉) 题。每题使用该知识点的诊断学习点（[内容 §3](content.zh-CN.md#3-知识点)）。

未解决的知识点按**未掌握**处理：定位宁可多教，因为重学已会的内容只花几分钟，而遗留的漏洞日后代价大得多。定位的知识点从 `placedRepNum` 起步，因此很快回来复习，侥幸的定位会在第一次复习时得到纠正。

## 10. XP

XP 近似专注学习的分钟数，由事件计算：

| 事件 | XP |
| :--- | :--- |
| 通过课程 | 知识点的 `xp` |
| 失败课程 | 0 |
| 通过复习 | max(3, round(xp / 3)) × 答对数 / 题数 |
| 失败复习 | 0 |
| 测验 | 15 × 答对比例 |

失败不得 XP：XP 奖励结果，因此它始终是对进度的诚实度量。失败花费的时间体现在日历上，正如 §8 中吃力学生多出的天数。
