# 学习引擎

> [English](learning-engine.md) | 简体中文

本文规定学习引擎：Great Academy 如何决定学习者下一步做什么，以及每次作答如何改变引擎对学习者的认识。引擎位于 `libs/engine`。它是纯的（没有时钟，除带种子的 `Rng` 外没有随机性，没有 I/O），并且与学科无关：它只看到编译后的知识图谱（[内容](content.zh-CN.md)）和学习者的事件日志。

它实现的教学法见 [Math Academy 之道](the-math-academy-way.zh-CN.md)。书中留有余地之处，本文记录我们的选择及理由；数值集中在 [§8](#8-参数)。

---

## 1. 状态与事件

引擎采用**事件溯源**。数据库把已完成的任务存为事件；学习者状态是对事件的折叠：

```ts
state = replay(ctx, events, initialState);   // 逐个事件调用 applyEvent
```

| 事件 | 记录时机 | 数据 |
| :--- | :--- | :--- |
| `placed` | 某门课程的诊断结束（或被跳过） | 课程；判定为已掌握的知识点；其中哪些被直接提问过 |
| `lesson` | 一节课结束 | 知识点、通过或失败、提问数与答对数、是否敷衍（§10） |
| `review` | 一次复习结束 | 知识点、答对数、提问数、是否敷衍 |
| `quiz` | 一次测验结束 | 每题一个结果，按知识点、是否敷衍 |
| `reading` | 一篇文章的检查结束 | 文章、答对数、提问数、是否敷衍 |

状态是推导出来的，因此参数或规则的改变通过重放作用于每位学习者，事件日志也就是每个决定的审计记录。

每个知识点的状态为 `TopicState`：

| 字段 | 含义 |
| :--- | :--- |
| `learned` | 课程已通过，或诊断判定已掌握 |
| `repNum` | 成功的间隔重复次数，可为小数 |
| `last` | 上次重复的有效时间 |
| `speed` | 该学习者掌握该知识点的快慢，取值 [0.5, 1.5]；1 为典型 |
| `failedAt` | 最近一次课程失败的时间 |
| `explicitReviews` | 已做的复习次数，用于分析 |

## 2. 记忆

记忆保持遵循指数遗忘曲线，间隔随每次成功重复而增长：

```
interval(repNum) = min(1 天 · 2.5^repNum, 365 天)
memory(now)      = 2^(−(now − last) / interval(repNum))
```

当记忆降到 0.5，即上次重复后一个间隔时，知识点**到期**：课后 1 天，然后约 2.5、6、16、39 天，依此类推。`repNum` 是小数，因此部分得分会平滑地延长间隔。

## 3. 前沿

课程是学科图谱上的一个视图（[内容 §6](content.zh-CN.md#6-课程)）。课程的**范围**是课程知识点加上其基础；掌握下限及其祖先**视为已知**，不讲授也不复习。

**前沿**是学习者下一步可以学的知识点：在范围内、尚未学会、所有先修都已知。按教学顺序列出（先基础，后课程顺序）。

**失败的课程。** 课程失败的知识点会离开前沿，直到它的每个关键先修在失败之后得到一次重复（显式或隐式）。失败通常意味着某个先修薄弱，因此引擎先修补先修，而不是立即重试同一节课。关键先修是各学习点 `keyPrerequisites` 的并集；都未声明时取直接先修。引擎会主动提供这些**补救复习**，排在所有复习之前，无论这些先修是否到期（§5）。否则，剩下的课程都失败了的学习者在这些先修恰好到期之前将无课可学：一个模拟的吃力学生曾因此几个月只做到期复习。

## 4. 重复与 FIRe

每次显式重复（一节课、一次复习、一道测验题）都有一个取值 [0, 1] 的**结果**，并沿涵盖边传播。这就是**分数隐式重复**（FIRe）。

**涵盖闭包。** 若 A 以权重 w₁ 涵盖 B，B 以 w₂ 涵盖 C，则 A 以 w₁·w₂ 涵盖 C。存在多条路径时取最大乘积。

**得分（结果 > 0）。** 知识点本身得分 `result`，它涵盖的每个已学知识点得分 `result · w`。得分 f：

- 给 `repNum` 加上 `f · early · speed`；
- 把 `last` 向当前时间移动 f 的比例，使记忆按得分比例恢复。

`early` 对到期前的重复打折：刚重复过（记忆 1）为 0，到期后（记忆 ≤ 0.5）为 1，中间线性。复习仍然新鲜的内容几乎不会加强它，这与间隔效应一致。

学习者**较慢**（speed < 1）的知识点**不接受隐式得分**。在某知识点上吃力的学习者需要显式练习它；来自更难知识点的得分会掩盖弱点。

**惩罚（结果 0）。** 知识点失去一次重复，记忆被重置（`last` = 当前时间），因此很快再次到期。涵盖它的每个已学知识点失去 `w · 0.5` 次重复，但不重置记忆：它们依赖失败的技能，应该更早回来，但它们本身并未被证明已遗忘。

## 5. 任务

`nextTasks` 最多提供六个任务：

1. 学习者在该课程中被定位之前，只提供**诊断**（§9）。
2. 测验到期时（§7），提供**测验**。
3. 阅读低于它在 XP 中的份额时（见下），提供一篇**文章**。
4. **复习**与前沿上的**课程**交替排列，复习在前；连续四次复习之后，课程在前。复习先是失败课程所等待的补救复习（§3），再是其余到期知识点经压缩后的复习。

**阅读。** 课程列出阅读单元后才提供阅读。下一篇文章是课程中第一篇满足以下条件的文章：学习者没有读过；它在单元中的前一篇已读；它的知识点都已掌握；已知词比例达到 `readingKnownShare`。只有尚未掌握的知识点所教授的词才算未知词。当 `readingXp` 低于全部 XP 的 `readingXpShare` 时提供文章，这样总是选第一个任务的学习者也会阅读。一篇文章读过一次后不再提供，无论是否通过，因为它已不能检验理解。前沿、复习和测验不依赖阅读。

检查显示读懂时（至少答对一半），文章的每个知识点得到 `readingCredit × weight` 的隐式得分，条件与其他隐式得分相同。检查失败既不加分也不扣分，因为可能只是文章太难。

**课程占比。** 有课程可学时，至少 25% 的任务是课程。复习从不挤占新学习；而且如下一点所述，新学习也是最便宜的复习方式。顺序同样重要，因为许多学习者总是选第一个任务：状态记录上次课程以来的复习次数，连续四次之后课程排在最前。否则，一个复习屡屡失败、又屡屡到期的学习者可能几周都只在复习。

**重复压缩。** 到期知识点不逐个复习：

1. 保证提供的课程会隐式修复的到期知识点（以权重 ≥ 0.5 被涵盖）先被去掉。
2. 其余的按集合覆盖贪心处理：每一步选择一个已学知识点，它的重复能修复最多尚未覆盖的到期知识点（它自己以及它以权重 ≥ 0.5 涵盖的到期知识点）；平局时优先自身到期的，再优先更高阶的。

这样，一次高阶知识点的复习就能代替其中若干较简单知识点的复习。

## 6. 课程与复习

**课程。** 一节课按顺序走过知识点的各学习点。每个学习点先读讲解和例题，再回答该学习点生成器出的练习题：

- **连续**答对两题，通过该学习点；
- 一旦在五题之内已不可能通过，课程立即**失败**。

**只练习**的知识点（[内容 §3](content.zh-CN.md#3-知识点)）直接从练习题开始。课程失败的学习者再回来学时，才会看到讲解和例题。

要求连对而不是累计答对，侥幸猜对就不够；在五题处停止，避免吃力的学习者反复磨题：引擎会把他们转向先修（§3）。

课程通过后：

- 知识点以 `repNum` 0 记为已学；
- 估计 `speed = 0.5 + fewest / asked`，其中 `fewest` = 学习点数 × 2（完美的一节课得 1.5）；
- 视为对其涵盖知识点的一次完整重复。

**复习。** 一次复习问三道题，从知识点最后（最完整）的学习点开始取题并打乱顺序。答对两题或以上即通过，结果为 `correct / 3`；否则失败（结果 0）。每次复习也调整速度：`speed ← 0.8 · speed + 0.2 · (0.5 + correct / total)`。

## 7. 测验

每获得 150 XP，且已学知识点至少四个时，提供一次测验：八道题，每题一个知识点，没有提示，结束前没有反馈。四分之三的题目来自最近学会的知识点，其余从较早的知识点中抽取。

每道答对的题是一次结果为 0.5 的显式重复，每道答错的题是一次失败（§4）。测验是提取练习式的检验：它能发现模型安排的复习遗漏的问题。

## 8. 参数

| 参数 | 值 | 理由 |
| :--- | :--- | :--- |
| `baseIntervalDays` | 1 | 课后第二天第一次复习，与书中一致 |
| `intervalGrowth` | 2.5 | 间隔重复系统常用的难度系数（SM-2 从 2.5 起） |
| `maxIntervalDays` | 365 | 每个知识点每年至少复习一次 |
| `dueMemory` | 0.5 | 恰好一个间隔后到期；约 50% 保持率时复习既高效，又有足够的"合意困难" |
| `failPenalty` | 1 | 一次失败抵消一次成功重复 |
| `implicitPenaltyScale` | 0.5 | 涵盖它的知识点分担责任，但只分一半，因为它们本身没有被检验 |
| `minCoverWeight` | 0.5 | 只有练到某到期知识点的至少一半，才算修复了它 |
| `minSpeed`、`maxSpeed` | 0.5、1.5 | 速度缩放得分；上下界防止单节课起支配作用 |
| `placedRepNum` | 1（被直接提问 +0.5） | 定位的知识点已掌握但近期未练习；直接答对是更强的证据 |
| `inferFoundationsMinAnswers` | 8 | 回答太少，不足以说明整体的先修基础 |
| `inferFoundationsRate` | 0.85 | 容许已掌握基础、偶尔失误的学习者通过；缺一半基础的学习者约为 0.5 |
| `adviceMinTopics` | 5 | 前面课程的知识点太少，不足以把学习者送回那门课 |
| `adviceWeakShare` | 0.3 | 前面课程在基础中的部分缺了近三分之一，靠途中的课已难以从容补上 |
| `adviceAheadShare` | 0.8 | 已掌握一门课五分之四的学习者，在下一门课里学到的更多 |
| `kpStreak` | 2 | 连对两题靠运气不太可能，而真懂的学习者又很快完成 |
| `kpMaxQuestions` | 5 | 容许一两次失误；再多，先修出问题的可能更大 |
| `reviewQuestions`、`reviewPass` | 3、2 | 简短的复习，容许一次失误 |
| `quizEveryXp` | 150 | 按每天 40 XP 约三到四天一次 |
| `readingKnownShare` | 0.98 | 已知词比例的起始目标，由试点调整 |
| `readingXpShare` | 0.2 | 阅读量重要，但不能挤占前沿；由试点调整 |
| `readingCredit` | 0.25 | 阅读对知识点的练习较轻，远少于复习 |
| `readingFailedXpShare` | 0.5 | 检查失败时，时间也已经花了 |
| `readingRushWpm` | 600 | 比任何人读懂文章的速度都快 |
| `quizQuestions`、`quizMinTopics` | 8、4 | 足以广泛抽样，又能一次做完 |
| `quizCredit`、`quizXp` | 0.5、15 | 一道题相当于半次复习 |
| `minLessonShare` | 0.25 | 每四个任务至少一个是新学习 |
| `maxReviewStreak` | 4 | 约半个学习日；没有哪一天只在复习。取三时，课程排到了其先修知识点的复习之前，拖慢了典型学习者 |
| `xpPerfectBonus` | 2 | 对全对的小奖励，与 Math Academy 相同 |
| `xpNearlyPerfect` | 0.8 | 五题错一题不扣分 |
| `xpNearlyPassable`、`xpNearlyPassableShare` | 0.5、0.15 | 失败但答对一半的课程也是真实的付出，所以得一点 XP |
| `rushSeconds`、`rushMinAnswers` | 6、2 | 六秒不足以读完题目和上一题的反馈再思考；这样的答案出现两次就不是偶然 |
| `blowOffStep`、`blowOffMaxPenalty` | 3、10 | 前三次 0 XP 作为警告，之后每三次多扣 1 XP，最多 10 |
| `blowOffDecay` | 0.2 | 通过五个任务抵消一次敷衍，这样穿插通过的任务也逃不过惩罚 |
| `forecastOverhead` | 1 | 模拟的典型学生每得 1 XP 课程 XP，短课程还会得 0.6 XP 复习和测验 XP，长课程约 1.3 XP |

这些数值来自书中的描述和我们的判断，而不是数据。路线图 P10 将根据真实学习者的事件日志重新校准，重放使改动对过去同样生效。

**模拟。** `tools/simulate` 用真实内容和引擎让模拟学生学完一门课程。学生答对的概率为 `ability · (0.6 + 0.4 · memory)`，每天学习固定的 XP。在代数基础（20 个知识点）上，每种学生 20 个种子的结果：

| 学生 | 能力、XP/天 | 天数 | 每知识点显式复习 | 失败课程 |
| :--- | :--- | ---: | ---: | ---: |
| 强 | 0.95、40 | 7.7 | 0.31 | 0.05 |
| 典型 | 0.85、30 | 10 | 0.76 | 1.8 |
| 吃力 | 0.70、20 | 16.6 | 2.36 | 11.3 |
| 典型、已会整数 | 0.85、30 | 7.7 | 0.93 | 1.4 |

典型学习者每个知识点不到一次显式复习，因为后面知识点的课程隐式复习了前面的知识点。吃力的学习者得到更多显式练习：他们较低的速度使隐式得分被扣留。模拟器的测试防止这些性质退化。

在代数预备（218 个知识点，加上它所依赖的算术知识点）上，同样的学生需要更多显式复习：典型学生 350.7 天、每知识点 4.31 次复习，强学生 3.88 次，吃力学生 6.19 次。在模拟器的 365 天内，典型学生 20 次运行中有 14 次学完，吃力学生一次也没有。这门课广而不深：它的许多单元（比与百分数、科学记数法、根式、统计、几何）在课程中很少被后续知识点练到，所以它们的复习较少来自隐式重复。涵盖它们的知识点将随代数一和几何课程出现。涵盖权重记录的是每个知识点实际练习的内容，不会为了改善这些数字而调高。没有手写包含边的知识点使用 [content.zh-CN.md](content.zh-CN.md) 所述的推断包含边，它们对强学生帮助最大：在四年级数学上，每知识点复习次数强学生从 3.14 降到 2.30，典型学生从 3.84 降到 3.38，吃力学生从 5.13 降到 5.11；在线性代数上，强学生从 3.41 降到 3.27，典型和吃力学生基本不变。

在代数一（234 个知识点，另加它们所依赖的代数预备知识点，因为模拟学生从零开始）上，典型学生需要 302.0 天、每知识点 4.30 次复习，强学生 3.81 次，吃力学生 6.26 次，20 次运行中只有 2 次在 365 天内学完。对包含关系的一次审查（记录每个知识点的题目真正练到的先修知识点）使典型学生的复习次数下降了约 3%。剩下的复习大多落在还没有后续知识点练到的知识点上，如工程与混合问题、硬币问题、垂线、韦达定理、根式方程和利润模型；在后面的单元以它们为基础之前，它们只能单独复习。

```bash
pnpm nx run simulate:simulate                  # 代数基础
pnpm nx run simulate:simulate -- prealgebra    # 其他课程
```

## 9. 诊断

学习者初次进入某门课程时，通过一次自适应诊断定位，诊断范围是该课程范围内尚未掌握的知识点。每门课程有各自的诊断，只做（或跳过）一次（状态中列出已诊断的课程）；在本学科其他课程中已学会的知识点不会再问，没有待定位知识点的课程没有诊断。每次作答解决的不只是所问的知识点：

- **答对**：该知识点及其所有祖先都已掌握；
- **答错**或"我不会"：该知识点及其所有后代都未掌握。

下一题选择使 min(答对时解决的知识点数, 答错时解决的知识点数) 最大的未解决知识点，即在图上做二分查找。n 个知识点的诊断最多问 min(n, 4 + ⌈2·log₂(n+1)⌉) 题。每题使用该知识点的诊断学习点（[内容 §3](content.zh-CN.md#3-知识点)）。

未解决的课程知识点按**未掌握**处理：定位宁可多教，因为重学已会的内容只花几分钟，而遗留的漏洞日后代价大得多。先修基础不同：宽泛的课程有数百个先修，再多可接受的题数也解决不完，全部掌握的学习者会被迫上数百节不需要的课。因此，当先修题的回答表明学习者已掌握时，未解决的先修按已掌握定位：至少回答 `inferFoundationsMinAnswers` 题，其中至少 `inferFoundationsRate` 答对。否则按未掌握处理；回答已表明未掌握的先修绝不会被定位。

定位的知识点从 `placedRepNum` 起步，因此很快回来复习，侥幸的定位会在第一次复习时得到纠正。

**当前课程。** 与 Math Academy 一样，学习者在每个学科有一门当前课程。它在账号开始学习时选定：成年人和青少年自己选，儿童由监护人选。它只能通过有意的选择改变，在设置中或回应下面的报告时，儿童的课程只能由监护人改。课程页面只介绍课程，不能选修。进度属于学科，所以在一门课里学会的知识点，在所有包含它的课程里都算数，换课不会丢失任何东西。过去的课程作为历史保留。

**报告。** 诊断问过题之后，仪表盘显示一份报告，直到选课的人保留这门课或换到推荐的课：已定位为掌握的本课知识点、还要学的基础、按几种每日学习量完成本课的日期，以及 `placementAdvice`（`libs/engine/src/courses.ts`）的建议：

- **往后**：本课 XP 中至少 `adviceAheadShare` 已掌握，且有课程以它为基础时，推荐第一门这样的课程；
- **往前**：答题显示前面某门课有缺口时，推荐最靠前的那门。每门课声明它以哪些课程为基础（[内容 §6](content.zh-CN.md#6-课程)），前面的课程从最近的开始查找。对每门课，只计它在本课基础中、且答题已解决的知识点：定位为掌握的，以及显示未掌握的，即答错的知识点和依赖它们的一切。计入的至少有 `adviceMinTopics` 个，且缺口至少占其 XP 的 `adviceWeakShare` 时，这门课算薄弱；
- 否则**保留**，跳过的诊断也总是保留。

未解决的知识点虽然定位时会教，却不算缺口：算进去会把每个学习者都送回第一门课。为此，`placed` 事件记录答错的知识点。

**标签与课程结束。** 作为课或复习提供的基础会标出它来自的课程：最近的、讲授它的前面课程，否则是目录中第一门讲授它的课程。当前课程的所有知识点都学会后，仪表盘提供以它为基础的课程。

## 10. XP

XP 近似专注学习的分钟数，由事件计算。每个任务有一个**满额 XP**：课程是知识点的 `xp`，复习是 max(3, round(xp / 3))，测验是 15，阅读是文章的 `xp`。实得多少取决于完成情况：

| 任务 | XP |
| :--- | :--- |
| 课程全对 | 满额 + 2 |
| 通过课程，答对至少 80% | 满额 |
| 通过课程，答对不足 80% | 满额 × 答对比例 |
| 失败课程，答对至少 50% | max(1, round(满额 × 0.15)) |
| 失败课程，答对不足 50% | 0 |
| 通过复习或测验，全对 | 满额 + 2 |
| 通过复习，有错题 | 满额 × 答对比例 |
| 失败复习 | 0 |
| 测验，有错题 | 满额 × 答对比例 |
| 阅读，至少答对一半 | 满额 |
| 阅读，答对不足一半 | 满额 × 0.5 |
| 敷衍的任务 | 0，屡次之后更低（见下） |

所以 XP 奖励结果，也承认诚实的努力：做得差的课程不得 XP，它花费的时间体现在日历上，正如 §8 中吃力学生多出的天数。

**敷衍的任务。** 任务未通过，且至少两道错题（占其错题的至少一半）在题目发出后六秒内就交了答案，就算敷衍。时间由服务器按题记录，客户端无法影响。慢慢做而失败绝不算敷衍，快速通过也不算，诊断也不在此列。事件以 `blownOff` 记录判定，所以重放不需要这些时间。

阅读任务在检查失败、且文章的词以快于 `readingRushWpm` 的速度掠过时算作敷衍：学习者先读后答，只看答题说明不了花了多少时间。

状态用 `blowOffs` 累计近期敷衍的次数。一次敷衍的惩罚是计入它之前的 floor(blowOffs / 3) XP，上限为 10 和该任务的满额：前三次不扣分，作为警告，接下来三次扣 1 XP，依此类推。每通过一个任务，计数减少 0.2。一个学科的 XP 总数不会低于零。学习者会在结果页看到警告及其含义。

## 11. 目标与预测

学习者可以给每周的每一天设一个 XP 目标，也可以暂停。一周的目标是它们的和；面板按学习者的时区把今天和本周的 XP 与之比较。

一门课程的预测，是尚未学会的课程 XP × (1 + `forecastOverhead`)，除以每天 XP 的速度：学习者最近 14 天的平均速度，以及几档固定速度作为对照。它是估计值，以日期显示，并随学习者的实际行动变化。

## 12. 联赛

联赛是可选的。学习者选择一个公开的用户名并开启后加入；别人只能看到用户名和本周 XP。

- **周。** 联赛周从周一 00:00 UTC 开始，所以对所有人是同一周。总 XP 不受影响；每周排名从零开始。
- **段位。** 九个段位：黑铁、青铜、白银、黄金、铂金、蓝宝石、红宝石、翡翠、钻石。新成员从黑铁开始。
- **小组。** 一周中第一次得到 XP 时，学习者进入所在段位的一个最多 30 人的小组，优先选择速度档相同且未满的小组。速度档来自最近四周的 XP（每周不足 100、250、500，或更多），让成员之间跟得上彼此；平台较小时满员的小组少，所以速度档只是优先条件。
- **周末结算。** 按 XP 排名，相同时先加入者在前。前三分之一（向上取整）升段，后三分之一（向下取整）降段，到顶和到底的除外。周末 XP 为零的成员不能升段，除黑铁外都会降段。
- **缺席。** 每缺席整整一周，段位降一级。暂停目标不能保住段位。

没有定时任务：结果由小组成员和不可变的事件日志决定，所以在需要时才计算。
