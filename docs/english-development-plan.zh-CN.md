# 英语开发计划

> [English](english-development-plan.md) | 简体中文

本文把[英语课程体系](english-curriculum.zh-CN.md)的设计变成里程碑：改什么、改哪些文件、每项如何验收，以及哪些结果才能开启下一阶段。设计文档说明英语是什么；本文说明按什么顺序构建。

---

## 1. 工作的组织方式

| 阶段 | 交付 | 需要外部提供 | 结束于 |
| :--- | :--- | :--- | :--- |
| 0 准备 | 决策、审核人员和已部署的平台 | 审核人员、法律意见 | 关卡 G0 |
| 1 首个切片 | 3 到 8 年级的语法、句子写作和词汇，由规则判定 | 试点学习者 | 关卡 G1 |
| 2 阅读与写作 | 分级阅读、知识单元、由 AI 判定的段落和文章 | 人工评分者、模型密钥 | 关卡 G2 |
| 3 外语课程 | A1 到 B1、音频、录音、S1 到 S4 | 语音供应商、人工评分的录音 | 关卡 G3 |
| 4 对话与两端 | 语音服务上的 S5 和 S6、自然拼读、大学写作、考试课程 | Kubernetes 集群 | 每门课程达到各自标准 |

```text
G0 ─► E1 首个切片 ─► G1 ─┬─► E2 阅读 ──────────┐
                         ├─► E3 AI 写作 ───────┴─► G2 ─► E4 外语课程 ─► G3 ─┬─► E5 对话
                         │                                                 ├─► E6 自然拼读
                         └── P6 移动端任务播放器（E4.7 需要）                └─► E7 大学和考试
```

**每个里程碑都遵守的规则。**

- 每个阶段都不影响数学：数学的测试、Worker 和学习者状态与之前一样。
- 阶段不需要的东西不提前构建。首个切片没有 AI、音频或新的 Cloudflare 产品。
- 标为*初始值*的阈值是有待数据确认的第一版数值，和引擎参数一样。
- 工作只估规模，不定日期，因为最长的等待来自人：**S** 是一个包内的几次提交，**M** 跨多个包，**L** 是新服务或大量内容。
- 每个里程碑按 [AGENTS.zh-CN.md](../AGENTS.zh-CN.md) 的要求，以两种语言更新它涉及的文档。阶段完成时更新[路线图](roadmap.zh-CN.md)。

## 3. 阶段 1：首个切片

### E1. 目标

[设计文档 §11](english-curriculum.zh-CN.md#11-首个切片) 的 41 个主题，从编译器一直到真实学习者，检验掌握学习和隐式复习在英语中是否有效。

### E1.1 学科骨架（M）

| 工作 | 文件 |
| :--- | :--- |
| 学科的检查器和辅助函数 | 新建 `libs/subject-english` |
| 内容包，包含 `compileEnglish()`、分片和测试 | 新建 `content/english`，参照 `content/math` |
| 认领和交接课程 | 新建 `content/english/PROGRESS.md` |
| 网关和一个分片，即 `ga-english` 和 `ga-english-core`；`generate` 写入清单 | 新建 `apps/english-workers`，参照 `apps/math-workers` |
| 绑定 `SUBJECT_ENGLISH` 及其网关 | `apps/web/cloudflare.config.ts`、`apps/web/src/server/handler.ts`、`apps/web/vite.config.ts`、`apps/web/package.json` |
| 只认识数学的工具改为接受学科参数 | `tools/simulate`、`tools/audit`（`compileMath`、`docs/math-courses`），大纲放在新建的 `docs/english-courses` |

**完成标准：** 含两个占位主题的课程与数学一起出现在目录中，能在 `cf dev` 中完成一节课，并且两个学科同时加载在一个 isolate 中时不超内存限制（`Registry` 在内存中保留两个学科）。

### E1.2 核心改动（M）

| 工作 | 文件 | 原因 |
| :--- | :--- | :--- |
| `CourseDef.explanationLocale`；服务器用该语言读取讲解、题目和判定结果，界面保持自己的语言 | `libs/content`、`libs/api` | 母语课程无论界面语言如何都用英语讲解 |
| `content/english` 增加抽样规则，拒绝未转义的 `$`；`\$` 已能写出字面的美元符号 | `content/english` | 文本是 Markdown，`$…$` 之间是 TeX，所以 `It costs $5 or $6` 会被渲染成公式 |
| 题库辅助函数：按种子选取，并按种子打乱选项和句子 | `libs/subject-english` | 英语没有可供生成的随机数 |
| 输入类型 `order`：移动列表项来排序；回答列出下标 | `libs/content`、`libs/proto`、`apps/web` | `ordering-sentences-in-a-paragraph` |

受众、音频和阅读任务不在这里添加，等用到它们的阶段再加。

### E1.3 检查器（M）

核心的 `text` 检查器会转小写并合并空白，所以无法判定大小写和标点。`libs/subject-english` 增加：

| 检查器 | 接受 | 用于 |
| :--- | :--- | :--- |
| `sentence` | 列出的任一句子，大小写和标点必须一致，只规范化空白和弯引号 | 书写规范和改错 |
| `sentence-pattern` | 符合模式的句子，模式带可选项和可省略部分，如 `The dog barked(,) because it heard a noise.` | 合并和扩展句子 |
| `word-form` | 形式和拼写正确的词，带 `same`，让列出的拼写错误得到专门反馈 | 词汇 |

每个检查器的测试都包括：可接受的变体、差一点正确的回答、Unicode 标点以及生成器列出的错误。合并题指定连接词并提供分句，这样可以完整列出可接受的句子。学习者写出有效句子却被拒绝，就是题目的缺陷：由试点报告（E1.6）。

### E1.4 内容（L）

按以下顺序编写，因为每组都是下一组的前置，第一组还用来检验编写工具：

| 顺序 | 主题 | 审核 |
| :--- | :--- | :--- |
| 1 | `subjects-and-predicates`、`complete-sentences-and-fragments`、`coordinating-conjunctions`、`expanding-with-because-but-so`、`base-words-and-affixes` | 审核者全部阅读，先修改工具，再写其他内容 |
| 2 | 其余语法（14 个主题） | 审核者抽查 |
| 3 | 其余写作（12 个主题） | 审核者抽查 |
| 4 | 其余词汇（10 个主题） | 审核者抽查 |

每个主题有 2 到 4 个知识点，题库足够大（至少 8 道题），能通过抽样且同一节课内很少重复；每个生成器都有错误回答，讲解有两种语言。段落和句子都是原创的。词表就绪后，内容检查会拒绝超出课程词汇水平的题目。

**完成标准：** 41 个主题全部编译通过，生成器通过 `sampleGenerators`，审核者发现的缺陷已修复，包含关系的权重都记录了理由。

### E1.5 模拟（S）

`tools/simulate` 让模拟学生学完课程，检查他们能否完成、每个主题的显式复习是否少于同样广度的数学课程，以及是否存在无法到达或卡住后续主题的主题。英语的图谱有些地方较稀疏，所以结果异常时先检查边。典型学生每个主题需要 2.45 次显式复习，而广度相近的三年级数学是 3.84 次；大部分落在后续主题还未练习到的词汇主题上。权重不会为了改善这个数字而提高。

### E1.6 外部测试与试点（M，主要是等待）

| 工作 | 文件或负责人 |
| :--- | :--- |
| 不使用平台题目的纸质测试，两份等值试卷 | 审核者 |
| 除现有内容外，报告被拒绝但人工判断正确的回答 | `tools/pilot` |
| 招募 20 到 30 名 3 到 8 年级学习者并按[未成年人数据](minors-data.zh-CN.md#13-代码中的执行以及各项何时具备)的要求取得监护人签字同意；进行四周 | 项目负责人 |
| 如[路线图 §3](roadmap.zh-CN.md#3-试点)，每周看报告、修复、观察学习 | 团队 |

**关卡 G1。** 满足以下条件时开始阶段 2：

1. 学习者在外部测试中有进步。
2. 有效句子很少被拒绝：低于回答的 2%（*初始值*）。
3. 学习者的进度接近模拟速度。

如果学习者没有进步，接下来的工作就是研究方法，而不是增加内容。与审核者一起判断原因在内容、图谱还是方法本身。

## 4. 阶段 2：阅读与写作

E2 和 E3 彼此独立，可以同时进行。先用一次简短的技术验证解决[设计文档 §13.6](english-curriculum.zh-CN.md#136-构建前要确认) 留下的问题：

| 技术验证 | 完成标准 |
| :--- | :--- |
| `cf` 能否声明 Workflows、AI 绑定和 Rate Limiting | 已部署到测试 Worker，或选定并记录替代方案 |
| pi-ai 在 Workers 上通过 AI Gateway 和 AI 绑定对接真实供应商 | 用真实模型检查工具调用、无效参数、取消和流式传输；测得包体积和启动时间 |

### E2. 分级阅读与知识（L）

| 编号 | 工作 | 文件 |
| :--- | :--- | :--- |
| E2.1 | `PassageDef`：文本、级别、依赖的主题和词、问题；词库及编译器检查 | `libs/content`、`docs/content.zh-CN.md` |
| E2.2 | 按学习者计算已知词比例，这是纯函数，参数初始为 98% | `libs/engine`、`docs/learning-engine.zh-CN.md` |
| E2.3 | 任务类型 `reading` 和事件 `reading`，按时间给 XP，并给依赖主题部分学分；学习前沿、复习和测验不变 | `libs/engine`、`libs/proto`、`libs/db`、`libs/api` |
| E2.4 | 读过的文章不再作为理解检查出现；回放得到相同状态 | `libs/engine` |
| E2.5 | 阅读播放器，记录阅读时间并检测敷衍 | `apps/web` |
| E2.6 | 3 到 5 年级的阅读，从 2 到 3 个知识单元开始，每单元约 10 篇 | `content/english` |

**完成标准：** 模拟学生的阅读任务占时合理，回放能重现状态，试点小组阅读时不会被生词淹没。试点同时检验 98% 这一参数。

**先于 G1 构建。** 项目负责人决定在第 1 阶段试点之前先构建 E2.1 到 E2.6。E2.6 已有前三个知识单元：地球上的水、植物怎样生活、尼罗河畔的生活，每单元 10 篇；模拟学生读完全部 30 篇，仍能学完课程。E2 的试点仍要等 G1。

### E3. 写作的 AI 判定（L）

| 编号 | 工作 | 文件 |
| :--- | :--- | :--- |
| E3.1 | 标准、路由、提示词和 `respond` 工具；每条引用都必须能在学习者文本中找到，否则结果被拒绝；用 `faux` 测试 | 新建 `libs/judge` |
| E3.2 | 每次判定一个 Workflow 的 Worker：重试、已校准的备用模型、时间和成本上限 | 新建 `apps/judge`，基于技术验证的结果 |
| E3.3 | 表 `judgment`：回答、状态、标准和引用、标准版本、模型、提示词版本、token、成本。`answer` 增加待判定状态和分数 | `libs/db` |
| E3.4 | AI 判定题的 `SubmitAnswer` 返回待判定，`GetSession` 显示判定结果。会话等待结果。事件只在有结果时追加，因此回放不会调用模型 | `libs/proto`、`libs/api` |
| E3.5 | 没有 `canonical` 答案但有范文的题型；按级别设长度上限，取代 `CheckerRegistry` 中的 2000 字符 | `libs/content` |
| E3.6 | 同一题多次作答：反馈最多两点，学习者重写，修改后的版本通过 | `libs/api`、`apps/web` |
| E3.7 | 写作播放器：长文本框、草稿保存、等待状态、标出引用 | `apps/web` |
| E3.8 | `tools/calibrate`：在已评分的数据集上运行路由，按标准报告一致性，并写入可用的路由 | 新建 `tools/calibrate` |
| E3.9 | 每位学习者的限额、不含学习者文本的 AI Gateway 日志、成本告警；学习者文本放在明确分隔的数据中，并有提示词注入测试 | `apps/judge`、Cloudflare |
| E3.10 | 抽样人工检查线上判定，按路由跟踪偏移 | `tools/calibrate` |
| E3.11 | 供应商、路由和[供应商登记表](minors-data.zh-CN.md#12-供应商)的数据表与检查，代码中不出现供应商。起初由 `tools/calibrate` 写入；之后增加平台管理员角色和[管理后台](english-curriculum.zh-CN.md#131-ai-模型)，密钥只写不读，并记录修改日志 | `libs/db`、`libs/api`、`apps/web` |

**失败时的行为。** 判定失败绝不算答错。学习者看到判定延迟，可以去学其他课程。每门课程只能有一个进行中的会话，所以结果到来前无法继续这门课。超过时间上限仍失败的判定，让学习者重写或跳过，不记录结果。

**等待目标（*初始值*）。** 95% 的 W2 和 W4 判定在 30 秒内返回。W5 的文章在提交时结束会话，稍后显示结果。

**内容顺序。**

1. **W2 句意检查**，用于首个切片的合并句子主题，最便宜也最容易检查。
2. **W4 段落**，一次一个动作，用于 3 到 8 年级。
3. **W5 文章**，包括提纲、初稿和修改，用于 6 到 12 年级。

W6 属于 E7。

**校准。** 每个标准约需 100 篇（*初始值*）由两人独立评分的文本。路由与人工的 Cohen's kappa 和两人之间的 kappa 相差不超过 0.05（*初始值*）时才能上线。模型、提示词或标准版本有任何变化，都要重新校准。

**关卡 G2。** 满足以下条件时开始阶段 3：

1. 每条线上路由都已通过校准。
2. 抽样检查没有发现偏移。
3. 每位活跃学习者每月的成本已测得且可以接受。
4. 学习者在由人工盲评的外部写作测试中有进步。

## 5. 阶段 3：外语课程

### E4. A1 到 B1，以及听力和 S1 到 S4（L）

| 编号 | 工作 | 文件 | 完成标准 |
| :--- | :--- | :--- | :--- |
| E4.1 | 知识点上的 `audience`；`explanationLocale: "zh-CN"` 的课程 | `libs/content`、`apps/web` | 在测试课程中，成人初学者和儿童看到不同的例子 |
| E4.2 | 题目和讲解中的音频：离线合成脚本和经审核的声音，文件存入 R2 并按内容哈希命名，编译器检查每个文件是否存在 | `libs/content`、新建 `tools/audio`、`apps/web` | 音频有缓存，在慢速网络上也能播放 |
| E4.3 | S1 听力，因不需要麦克风而最先上线 | `content/english` | 辨音主题通过抽样，审核者检查过每个音频文件 |
| E4.4 | Web 录音并用短期 URL 上传到 R2，用生命周期规则删除文件，提供[未成年人数据](minors-data.zh-CN.md#9-文本与语音)的 `speech` 同意和麦克风检查；学习者可以跳过 | `apps/web`、`libs/api` | 录音按时消失，没有麦克风的学习者不会卡住 |
| E4.5 | `libs/judge` 背后的语音接口；用 200 段含语法错误的录音测试每个语音转文字服务是否悄悄纠错 | `libs/judge`、`tools/calibrate` | 选定 S4 的服务；如果没有服务能保留错误，就砍掉 S4 |
| E4.6 | [设计文档 §13.2](english-curriculum.zh-CN.md#132-录音口语) 的发音比较：200 到 300 段（*初始值*）人工评分的录音，包括中文母语者、其他口音和儿童，儿童录音需要[未成年人数据](minors-data.zh-CN.md#9-文本与语音)中单独的 `research` 同意 | `tools/calibrate` | 选定供应商，或在 S2 用目标词识别代替 |
| E4.7 | S2、S3 和 S4，低置信度时重录，先上 Web，P6 任务播放器就绪后上移动端，使用原生录音 | `apps/web`、`apps/nsh` | 低置信度时请学习者重录且不计失败，每个级别都有测试 |
| E4.8 | 课程按 A1、A2、B1 的顺序，包含面向中文母语者的主题（冠词、时态、复数、th、r 和 l），练习在四个方面保持平衡 | `content/english` | 每门课程编译通过、已审核，模拟中时间在四个方面保持平衡 |
| E4.9 | 用外部听说测试，对中文成人和其他母语者试点 A1 和 A2 | 团队 | 关卡 G3 |

**关卡 G3。** 学习者在外部测试中有进步，有口音但听得懂的语音很少被拒绝（低于 5%，*初始值*），所服务的每个市场都已完成录音的法律审查。之后 C1 和 C2 按设计并入母语课程。

## 6. 阶段 4：对话与两端

三条线彼此独立。E5 需要集群的具体信息；E6 需要 E4 的音频和录音。

### E5. S5、S6 和语音服务（L）

| 编号 | 工作 | 文件 | 完成标准 |
| :--- | :--- | :--- | :--- |
| E5.1 | S5 复述，沿用 E3 的路径，由语音转文字和 AI 判定要点覆盖 | `libs/judge`、`content/english` | 覆盖标准通过校准 |

### E6. 自然拼读（L）

幼儿园到 2 年级：声音与文字这条线，然后是朗读流利度（S3）和听力理解。这依赖 E4.2 和 E4.4，以及在儿童身上测试过的语音识别。学习时假定有成人在旁，所以监护人的体验也是工作的一部分：试点必须包括监护人，登录和同意流程可能需要修改。

### E7. 大学和考试课程（L）

- **大学及以上：** 研究写作、批判性阅读和 W6，可选人工审阅。人工审阅是产品决策，需要自己的计划和定价。
- **9 到 12 年级：** 修辞和文学，只使用公有领域的作品。
- **考试课程：** IELTS、TOEFL、Cambridge 和高考，是建立在现有主题上的纯练习课程。绝不复制考试的题目、文本和词表，课程开始时对照官方最新说明确认每种考试的形式。

每门课程在编译通过、通过抽样和审核、AI 路由完成校准时才算完成；同类的第一门课程还要在外部测试中显示出进步。

### 7.4 成本跟踪

每次 AI 和语音调用都记录 token 或秒数以及成本，按用途和课程分组。每道关卡都审视每位活跃学习者每月的成本；内容总成本尚未估算，从 E1.4 起按主题跟踪。

### 7.5 什么情况下计划会停下

- **G1 未通过：** 在弄清方法的问题之前，不再增加内容。
- **AI 无法在某项标准上达到校准要求：** 删除或拆分该标准，题目改由规则判定或作为人工审阅选项。不会为了通过检查而降低要求。
- **没有语音服务能保留错误：** S4 和 S5 依靠受限形式，S6 只作练习，不给语法打分。
- **法律意见禁止某市场的未成年人录音：** 该市场对未成年人关闭口语，阅读和写作照常工作，这正是设计的要求。
