# 管理后台

> [English](admin.md) | 简体中文

平台管理员在管理后台处理那些不应该靠改代码来做的事：使用哪些 AI 服务、哪些市场向未成年人开放、哪些监护人已通过验证。它位于 Web 应用的 `/admin`。它的限制来自[未成年人数据](minors-data.zh-CN.md)和[英语设计 §13.1](english-curriculum.zh-CN.md#131-ai-模型)。

## 1. 原则

1. **配置只做选择，不放宽规则。** 每次保存和使用时，服务端都检查校准、供应商登记表和市场规则。没有任何页面能绕过它们。
2. **学习者的文本和录音绝不出现在这里。** 后台只显示计数，不显示任何人写过或说过的内容。不存在代登录功能。
3. **密钥只进不出。** API 密钥可以替换，但不能读回；页面只显示最后四个字符。
4. **所有修改都留痕，** 记录修改人、时间和修改内容，不含密钥。
5. **尽量少接触个人数据。** 监护人的邮箱和签字表格只在等待决定时出现，决定后表格即被删除。

## 2. 谁能进入

平台管理员是 `platform_admin` 表中的一行。这个角色独立于监护人和学习者，不赋予产品中的其他权限。

- **第一位管理员** 通过命令行授予：`pnpm nx run db:grant-admin -- <email>`。没有任何注册途径能获得这个角色。
- **之后的管理员** 在“管理员”页面用已有成年人账号的邮箱添加和移除。管理员不能移除自己，所以这个角色不会被意外清空。
- **每个 `AdminService` 调用都在服务端检查角色。** 页面只是隐藏服务端本来就会拒绝的内容。已登录的非管理员看到的是未找到页面，所以后台透露的信息不超过这份文档。
- **未成年人不能成为管理员。** 只有成年人年龄段的账号才符合条件。

## 3. 页面

| 路由 | 页面 | 用途 |
| :--- | :--- | :--- |
| `/admin` | 概览 | 需要关注的事项：等待处理的表格、已过期或即将过期的登记核查、不再合格的路由、最近一天的费用告警、最近一次保存期限任务，以及各年龄段学习者的计数 |
| `/admin/verifications` | 监护人验证 | 等待处理的签字表格，最早的在前。打开表格后批准或附理由拒绝。无论哪种决定，表格都会被删除 |
| `/admin/markets` | 市场 | 每个市场一行：代码中的规则、是否向未成年人开放、需要的通知语言，以及目前能提供哪些 AI 范围 |
| `/admin/ai` | AI 服务 | 供应商及其预算，以及路由 |
| `/admin/costs` | 费用 | 每家模型供应商今天和本月的花费与预算的对比、本月每位活跃学习者的费用、告警、每个模型的价格，以及费用最高的学习者 |
| `/admin/checks` | 抽查 | 盲查抽样的线上判定，每次一项标准；以及各路由与人工的一致程度和校准时的对比 |
| `/admin/register` | 供应商登记表 | 每家供应商在每个市场核查了什么、何时核查 |
| `/admin/notices` | 通知 | 通知版本及其写明的供应商 |
| `/admin/admins` | 管理员 | 谁拥有这个角色；不经付款授予若干天的方案，用于测试人员、审核人员和试点（[计费](billing.zh-CN.md) §6） |
| `/admin/log` | 修改日志 | 所有修改，最新的在前，可按类型筛选 |

后台沿用产品的设计令牌和语言，并能在手机宽度下使用：等待监护人的表格不该非得坐到桌前才能处理。

## 4. 市场

市场的规则（监护人年龄线、范围、语言）是 `libs/api/src/markets.ts` 中的代码，因为修改它们是需要审阅的法律决定。后台保存的是上线开关，因为开放是运营决定。

- **每个市场一开始都不向未成年人开放。** 成年人不受影响。
- **开放需要记录：** 谁签字确认、何时确认。后台还会显示缺少哪些必需的通知语言，在语言齐备或管理员记录法律顾问接受这一缺口之前，拒绝开放。
- **中国大陆不能在这里开放。** 它在代码中的规则就是关闭，所以没有开关。重新开放是[单独的决定和项目](minors-data.zh-CN.md#5-中国大陆)。
- **关闭市场** 会立即阻止新的未成年人。已在学习的未成年人保留账号和数据，但在重新开放前无法学习，所以关闭是一项严肃的操作，需要确认。

## 5. AI 服务

**供应商。** 先从 pi-ai 的具名供应商目录中选择，或者手动设置。目录（`libs/judge/src/catalog.ts`）列出 pi-ai 内置的、使用 API 密钥、在固定地址上使用平台支持的 API 的供应商，不含面向编程工具的个人订阅（Copilot、编程套餐和 Token 套餐）；选择后自动填好名称、API 和基础 URL，并记下它的 id。手动设置的供应商从平台支持的 API 中选择一种，即它的接口在写作批改和口语对话中遵循的协议；大多数其他供应商和自建服务都兼容 OpenAI。只用于语音的供应商选「无」。随后是 API 密钥、预算和是否启用。供应商没有类型：它做什么由它的路由决定，所以同一家供应商只需一个密钥、每个市场一条登记，就能同时批改写作和把语音转成文字，卡片上会列出这些用途。供应商本身没有区域：供应商处理数据的地区可能因市场而异，所以由登记表的每条记录写明。来自目录的供应商使用目录中的 API，只有基础 URL 可以修改，例如经由网关。添加路由或价格时，从该供应商在目录中的模型里选择，选「其他模型」会出现一个输入框，填写目录中没有的名称（手动设置的供应商没有列表，模型直接填写）；新价格先按供应商标价填好，由管理员改成平台实际支付的价格。目录认识的路由模型沿用目录中的上下文长度、输出上限和请求设置，其他模型使用宽松的估计值。密钥用 AES-GCM 在 `AI_KEYS_SECRET` 下加密，这是数据库接触不到的 Worker secret。基础 URL 位于 `gateway.ai.cloudflare.com` 时，调用经过 Cloudflare AI Gateway：每次调用带上 `cf-aig-collect-log-payload: false`，网关只记录模型、token、费用、状态和耗时，不记录请求和响应；`cf-aig-metadata` 写明用途、标准和提示词版本，从不写学习者。

**路由。** 路由说明某项用途的某个对象由哪家供应商的哪个模型来做，分主路由和备用路由，有草稿和上线两种状态。页面按用途分组：

| 用途 | 对象 | 另需 |
| :--- | :--- | :--- |
| `judgment`，写作批改 | 标准，用它的键 `id@version` 命名（例如 `w4-topic-sentence@1`），所以标准的新版本需要自己的路由和校准 | 提示词版本 |
| `conversation`，S6 口语对话 | 对话的 id | 提示词版本 |
| `stt`，语音转文字 | 语言，如 `en` 或 `en-US` | |
| `tts`，文字转语音 | 语言 | 声音 |
| `pronunciation`，发音评分 | 语言 | |

路由的对象和提示词版本从服务端维护的列表中选择：各学科被判定主题的标准、`libs/judge` 中的提示词，以及语音语言；其他值一律拒绝。文本用途需要有 API 的供应商。写作批改和对话可以校准：对话的校准以对话的 id 作为标准，依据录制的测试对话（E5.12）。其他用途的路由要等语音服务和它们的校准到位，在此之前只能是草稿。

- **上线需要校准。** 只有这组标准、模型和提示词版本已有通过的校准，路由才能上线。校准由 `tools/calibrate` 写入，在这里只读；管理员不能录入。路由还必须抵御 `libs/judge` 中的每一条注入探针，校准才算通过：这些文本只由试图操纵评分者的话组成，有英文也有中文，路由必须判定它们不满足标准。
- **修改已上线路由的模型或提示词，它会回到草稿，** 因为换模型就是换评分者。
- **停用供应商** 会立即停止它的路由。

不再合格的路由按关闭处理：判定等待，或换到已校准的备用路由，概览页会提示。

**价格和预算。** 每个模型有一个以美元计的价格，按每百万输入和输出 token 计，在费用页录入；每家模型供应商可以设置每日和每月预算，按 UTC 的日和月计。对模型的每次调用，无论成败，都连同 token 和按该价格算出的费用记入 `ai_call`，校准运行也算在内，所以这份记录就是供应商的账单。

- **没有价格，就不服务学习者。** 模型没有价格的路由不服务任何学习者，如同未经校准。留空的预算表示不设上限；设置了的预算用完后，本期内不再接收新的文字。
- **预算用完，就不再接收新文本。** 供应商用完每日或每月预算后，它的路由不再接收新文本，这些路由判定的主题对学习者隐藏，直到下一天或下一月。已经接收的文本总会判定完，即使超出预算，这样没有学习者会等不到判定。预算用完不会让路由算作失效。

**每位学习者的限额。** 学习者在任意 24 小时内最多提交 30 篇文本供判定，重写也算在内，每分钟最多 5 篇；每次判定最多尝试 4 次。被拒绝的文本不会记录，学习者会被告知何时再来，其他课程照常进行。

**告警。** 每 15 分钟一个 Cron Trigger 检查费用，在以下情况发出告警：供应商的花费越过预算的 50%、80% 或 100%；模型每次调用的费用超过它最近 7 天平均值的两倍；或者模型当天的调用中超过 30% 失败（至少 10 次调用）。每条告警只写入修改日志一次，并通过电子邮件发给每位管理员。

**抽查。** 按判定的 id 选出一部分已完成的判定（*初始值* 5%），这样任何文本都无法影响是否被抽中；它的每项标准连同判定它的路由和判定结果，等待人工检查。抽查页显示最早等待的一条：任务、经过与模型调用相同过滤器的学习者文本（不显示学习者身份），以及该标准的问题。检查者先作答，再看路由的答案。打开的每篇文本和每个回答都按抽样的 id 写入修改日志，从不包含文本。文本已过期的抽样不再显示。

- **偏离。** 每条路由最近 90 天的抽查给出它与人工的一致率和 κ。路由至少有 30 条抽查、且 κ 比最新通过的校准低 0.1 以上，即为偏离（*初始值*）：抽查页会标出，费用检查每月发出一次告警。处理办法是重新校准，或把这项标准改到别的路由。

## 6. 供应商登记表和通知

**登记表** 为每家供应商的每个市场保存一条记录，包含[未成年人数据第 12 节](minors-data.zh-CN.md#12-供应商)的条件：服务该市场、条款允许未成年人、不用于训练、保留期限、数据处理协议、传输机制、供应商处理该市场数据的区域（必填，从列表中选择）、备注和核查日期。只有全部条件满足且核查未超过 12 个月（*初始值*），记录才有效。它表示有人核查过，日志记录是谁。

**通知。** 通知版本写明同意该版本后可以接收未成年人数据的供应商。发布写有新供应商的版本后，要等学习者重新同意才生效。通知文本和 `/legal` 页面都在代码中，以便经过审阅。

只有市场规则允许 AI，且当前通知写明了一家供应商，它有该范围所需用途的上线路由（`writing` 需要写作批改，`speech` 需要语音转文字），并且有当地的有效登记，市场才提供相应的 AI 范围。在此之前，不会有人被要求同意它。

只有同时满足以下条件，未成年人的数据才会发给供应商：

1. 学习者所在市场向未成年人开放。
2. 学习者对该范围有当前有效的同意。
3. 供应商在该市场有当前有效的登记。
4. 同意所对应的通知版本写明了该供应商。
5. 路由已上线，或是已校准的备用路由。

## 7. 后台之外

- **阅读学习者的文本、录音或回答。** 任何这类工具都必须独立、经过审批并有审计（[未成年人数据第 13 节](minors-data.zh-CN.md#13-代码中的执行以及各项何时具备)）。
- **修改学习者的年龄段，** 以及任何扩大未成年人可用范围的操作。
- **授予同意。** 只有监护人或学习者本人可以。
- **修改日志。** 日志只追加。
- **修改市场规则。** 它们是代码。
