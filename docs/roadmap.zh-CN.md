# 路线图

> [English](roadmap.md) | 简体中文

## 2. 风险与待定事项

- **内容量**是主要成本。覆盖一年级到本科高年级数学约需 4,100 个知识点，每个都要有 KP、例题和生成器。编写与评审工具比系统其他任何部分都重要。
- **引擎参数**来自书中的描述和我们自己的选择，而不是数据。它们记录在[学习引擎 §8](learning-engine.zh-CN.md#8-参数)，必须在 P10 重新校准。
- **`cf` 命令行**仍是 beta 版，配置格式可能变化。
- **Worker 体积与启动。** 学科运行在各自的 Worker 中，从本地测量看，每个都远低于 64 MiB 体积、1 秒启动和 128 MB 内存的上限（[架构](architecture.zh-CN.md) §6.1）。这已在本地 workerd 中跑通，但还没有部署到 Cloudflare，所以线上的启动时间、Worker 间调用延迟和内存占用都还没有测量。
- **原生应用中的数学内容**通过 Native Shell 的 `WebView` 实现，每段含公式的文本使用一个，需要在低端 Android 设备上验证。
- **原生应用的会话 token** 保存在 Native Shell 的 `Storage` 中，这是一个普通文件，没有钥匙串保护。发布前需要解决。
- **Native Shell 还很年轻。** 它的版本还是 0.x，应用需要的托盘和窗口尺寸等功能只在 main 分支上，所以应用从源码构建它；每次更新它都可能影响应用，等有了包含这些功能的发布版，应在 `mise.toml` 中固定版本。

## 3. 试点

测试和模拟学生能说明内容正确、引擎运行正常。内容能不能教会人，只有真实学习者才能说明。试点就是用来查明这一点的，而且必须由人来组织：需要招募学习者；未成年人还需要监护人同意。

**对象和内容。** 20 到 30 名学习 Algebra I 的学习者，为期四周，水平有高有低，每人每天约 30 XP。先选 Algebra I，因为它的学习者最多，先修内容也覆盖得好。

**在平台之外衡量学习效果。** 前后各做一次同类型的简短纸面测验，题目不取自平台。XP 和通过的课程是平台对自己的说法，测验才是对它们的检验。

**每周。** 运行报告并据此行动：

```bash
DATABASE_URL=… pnpm nx run pilot:report -- --course algebra-i --since 2026-12-01 --out /tmp/pilot.md
```

| 报告显示 | 怎么做 |
| :--- | :--- |
| 某知识点很少有人第一次就做对 | 读它的讲解和例题，补一步或拆分知识点。不要把题目改容易 |
| 多名学习者给出同一个错误答案 | 把它加为带专门反馈的错误，或在讲解中说明 |
| 某主题的课程失败很多 | 检查先修关系是否真的成立，以及中间是否缺一个知识点 |
| 任务开始了却被放弃 | 问学习者原因：长度、难度和显示问题的修法各不相同 |
| 每个学习日的 XP、每个已学知识点的复习次数与 `tools/simulate` 相差很大 | 弄清是学习者学得比计划少，还是需要更多重复：只有后者才是检查课程的理由 |
| 被拒绝的句子中有人工判定为正确的 | 把它们加入该题的句型。它们在全部回答中的比例就是[英语开发计划](english-development-plan.zh-CN.md)的门槛所看的数字 |

比率至少要有 5 名学习者才会列出；即便如此，它也只是值得细读的线索，不是结论。

**观察学习过程。** 每周观察两三名学习者边做课程边说出想法。这能发现数字看不到的东西：哪些句子被跳过，学习者在哪里不再相信讲解。

**试点要回答什么。** 学习者在外部测验上是否进步，学完课程所需时间与模拟速度相比如何，以及 P10 要拟合哪些参数（可靠性校准和每分钟 XP）。

报告只读取主题、知识点、作答和结果，不显示姓名。其来源数据库要像其他学习者数据一样对待。
