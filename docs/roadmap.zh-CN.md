# 路线图

> [English](roadmap.md) | 简体中文

本文列出各阶段、完成标准和当前状态。数学是第一个学科。每个阶段的设计都保持核心与学科无关（[架构 §1](architecture.zh-CN.md#1-原则)）。

## 1. 阶段

| 阶段 | 范围 | 完成标准 | 状态 |
| :--- | :--- | :--- | :--- |
| P0 基础 | Monorepo（mise、pnpm、Nx、TypeScript、Biome、Vitest）、文档 | 在干净的检出上 `pnpm nx run-many -t typecheck test lint` 通过 | 已完成 |
| P1 内容模型 | `libs/content`：知识点、KP、课程、题目的类型；编译器与校验器；带种子的题目运行时；答案判定 | 编译器能拒绝环、悬空引用、非法权重和非确定性生成器；每条规则都有测试 | 已完成 |
| P2 第一批数学内容 | `libs/subject-math`、`content/math`：从整数运算到一元一次方程与不等式的一段连通内容，中英双语，带先修边和包含边 | 内容能编译；每个 KP 的生成器各抽样 200 次，答案正确且自洽 | 已完成 |
| P3 学习引擎 | `libs/engine`：知识前沿、FIRe 重复模型、带重复压缩的任务选择、课程与 KP 流程、复习、测验、诊断、XP；`tools/simulate` | [学习引擎](learning-engine.zh-CN.md)中每条规则都有单元测试；模拟学生学完这段内容时，平均每个知识点的显式复习约一次或更少 | 已完成 |
| P4 契约与存储 | `libs/proto`、`libs/db`、`libs/api`：服务、schema、事件日志、仓储、会话执行器 | 仓储和服务在 PGlite 上通过集成测试；重放事件日志能还原已存储的状态 | 已完成 |
| P5 Web 应用 | `apps/web`：账户、课程目录、选课、诊断、任务面板、课程/复习/测验播放器、进度 | 新学习者能在 `cf dev` + PostgreSQL 环境中完成注册、诊断，并端到端地完成课程和复习 | 已完成 |
| P6 移动应用 | `apps/mobile`：登录、任务面板、复用数学组件的任务播放器 | 应用能在 iOS 模拟器中连接开发服务器运行 | 骨架：课程列表与大纲 |
| P7 内容扩充 | 补完 Prealgebra，然后 Algebra I → Precalculus → Calculus，依据[数学课程体系](math-curriculum.zh-CN.md)规划 | 每门课都能编译，并通过生成器抽样；边经过评审 | 进行中：代数预备核心（39 个知识点） |
| P8 账户与监督 | 家长和老师角色、托管的学习者档案、报告 | — | 计划中 |
| P9 计费 | 订阅：Web 用 Stripe，移动端用应用内购买 | — | 计划中 |
| P10 校准 | 用真实作答拟合知识点难度和引擎参数；逐题的内容分析 | — | 计划中 |
| P11 更多学科 | 在同一核心上实现第二个学科 | — | 计划中 |

## 2. 风险与待定事项

- **内容量**是主要成本。覆盖四年级到本科高年级数学约需 3,500 个知识点，每个都要有 KP、例题和生成器。编写与评审工具比系统其他任何部分都重要。
- **引擎参数**来自书中的描述和我们自己的选择，而不是数据。它们记录在[学习引擎 §8](learning-engine.zh-CN.md#8-参数)，必须在 P10 重新校准。
- **`cf` 命令行**仍是 beta 版，配置格式可能变化。
- **移动端的数学输入**通过 Expo DOM components（Web 视图）实现，需要在低端 Android 设备上验证。
